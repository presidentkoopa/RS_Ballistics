# ============================================================================
# RSBDEFS -- RS_Ballistics profiles.
#
# Any loaded package may ship an RSBDEFS lump. Every one is read, in load
# order, and a later profile with the same kind and name replaces an earlier
# one -- that is how a weapons or map package adds or overrides looks without
# code.
#
#     <kind> <name>
#       key = value, value, ...
#     end
#
# `#` starts a comment. Keys are case-insensitive. AN UNKNOWN KEY OR A BAD
# VALUE REFUSES THAT PROFILE, named with its lump and line; the other profiles
# still load.
#
# KINDS
#   style     a look the player picks in the menu: multipliers over everything
#   burst     one GPU particle emission -- the building block
#   (what textures are made of is the engine's: SURFACES.txt, not a kind here)
#   impact    what a landing round does, by surface
#   round      what a gun names: a pairing of ballistics and roundlook
#   ballistics how a round flies and hits (speed, radius, damage) -- the same on
#              every machine: no variants, no player setting
#   roundlook  how a round looks and sounds (sprite, glide, wake, impact, whiz)
#   wake       what a round sheds as it flies
#   flash     the muzzle: light, lit-air cone, bursts, flame, smoke
#   ejecta    spent casings and hulls
#
# VARIANT NAMES:  <base>[~style][.material][@tier]
#   impact bullet                   the default
#   impact bullet.metal             on metal
#   impact bullet@plain             at the plain tier
#   impact bullet~cinematic.metal   the cinematic style, on metal
# The most specific that exists is used. Material outranks style. A profile
# written for a tier is used as written; otherwise the tier scales counts
# (plain 0.4, normal 1, heavy 1.8, extreme 3).
#
# THIS FORMAT IS THE PROTOTYPE of the engine's effect-definition lump
# (Engine docs/ENGINE_SUPPORT_LIST.md): keep kinds and keys general.
#
# GPU PARTICLES. A burst with no `particle` is inline additive glow (sparks, chips,
# glints). A burst with `particle = <definition>` draws a PARTICLEDEFS definition,
# which can be lit, alpha-blended, soft and textured (dust, smoke, flame puffs).
# ============================================================================

# ---------------------------------------------------------------- BURSTS
#   count       particles
#   cone        half-angle, degrees
#   speed       map units per second, jitter 0..1
#   life        seconds, jitter
#   color       r, g, b
#   glow        brightness (additive)
#   size        start, end (diameter, map units)
#   gravity     map units per second^2 (negative rises)
#   drag        1/s
#   orient      billboard | streak | flake
#   stretch     streak length, seconds of travel
#   aim         normal | reflect | back | along | up
#   offset      map units off the surface

# ---------------------------------------------------------------- MATERIALS
# What textures are made of is the ENGINE's now (surface materials, #16):
# RS_Ballistics' SURFACES.txt tags them and TexMan.GetSurface answers. The
# impact variants below (.metal, .wood, .glass, .liquid, .dirt) use those
# names; a surface another mod's SURFACES adds gets variants the same way.
# A `material` block here is refused.


# ---------------------------------------------------------------- IMPACTS
#   bursts      burst names, or none
#   mark        shape, radius (map units), life (tics)
#               shapes: pool bar gouge ring hexfield hexring spiral boxring
#                       star sunburst grid invert box
#   markcolor   r, g, b
#               A mark GLOWS, so only a hot hit leaves one (owner: only hot things
#               glow): metal a round strikes, energy, blasts, burns. Never stone,
#               wood or dirt; their holes wait for the engine's wall damage (#17).
#   sound       SNDINFO name | none
#   light       radius, intensity, tics      lightcolor  r, g, b
#   glance      degrees from the surface, sound, burst -- a ricochet
#   vary        count <0..0.9>, size <..>, light <..> -- each hit that part comes out up
#               to this much bigger or smaller (hashed per hit)
#   maybe       <burst> <chance 0..1>, ... -- bursts only some hits throw
#   heat        radius, strength, tics -- heat shimmer where it lands, fading (the
#               engine's; turned on in Ballistics & Effects, Heat shimmer)
#   scale       count, size -- every burst's particle count and size times these:
#               how hard a class of round bites (a pistol a little, a rifle a lot,
#               one pellet of buckshot little). 1, 1 when not given

  sound     = rsb/impact/concrete

# ---------------------------------------------------------------- ROUNDS
# A ROUND PAIRS TWO PROFILES, so how it flies and hits stays apart from how it
# looks -- which is what lets looks be customised per player safely.
#
#   ballistics <name>   what the GAME knows. Read exactly as written on every
#                       machine: no ~style, .material or @tier variants (refused),
#                       and no player setting reaches it.
#     speed   map units per tic (34 map units = 1 meter, 35 tics a second)
#     radius  map units
#     damage  base, dice  -> base x 1d(dice), unless the shooter sets damageMin/Max
#
#   roundlook <name>    what a PLAYER sees and hears. Style and tier variants
#                       allowed (roundlook pistol_45~cinematic, pistol_45@heavy).
#                       The menu's Round look swaps what flies (look, glide, wake)
#                       for any roundlook; impact and whiz stay the round's own.
#     look    sprite, <4-letter sprite> | none (nothing drawn in flight)
#     glide   yes | no
#     wake    <wake> | none
#     impact  <impact base> | none
#     whiz    radius (map units), sound -- a near miss past the listener's head
#
#   round <name>        what a gun names (WM_Gun.RoundProfile)
#     ballistics = <ballistics name>
#     roundlook  = <roundlook name>

# ---- ballistics

# ---------------------------------------------------------------- FLASHES
#   light       radius, punch, tics      lightcolor  r, g, b
#   cone        inner, outer (degrees), length, density
#   conetics    tics
#   bursts      burst names | none
#   flame       sprite scale (0 = none)
#   smoke       count, scale, alpha
#   smokeparticle  <PARTICLEDEFS definition> | none -- GPU smoke (count x 2 puffs)
#                  instead of sprite puffs; scale and alpha then unused
#   heat        radius, length, strength, tics -- heat shimmer out of the muzzle
#   vary        light <0..0.9>, flame <..>, cone <..>, sparks <..>, smoke <..> -- each shot
#               that part comes out up to this much bigger or smaller (hashed per shot)
#   maybe       <burst> <chance 0..1>, ... -- bursts only some shots throw
#   surge       chance, scale -- now and then a bigger shot: all of it x scale
#   flameroll   yes | no -- the flame sprite turns to a new angle each shot (yes)
#   barrelheat  heat a shot, heat lost a second, smokes from -- THE SMOKING BARREL: after a
#               quick string of shots the barrel smokes, hardest at heat 1, until it cools.
#               Needs the gun mod's RSB_Barrel.Shot and RSB_Barrel.Muzzle calls (barrel.zs).
#   barrelsmoke <PARTICLEDEFS definition>, puffs a tic at full heat -- the ribbon off the muzzle
#   barrelshimmer  radius, strength -- the hot air bending over the barrel
#

# bfg and rail have their own light and sparks, and `none` is no flash at all.

# ---------------------------------------------------------------- FLAMES
#   reach        map units the stream carries
#   speed        the fuel's speed, map units per second
#   spread       degrees the stream wanders
#   stream       bursts fired from the nozzle every tic. FOR THESE, a burst's
#                speed and life are MULTIPLIERS: of the fuel speed, and of the
#                time the fuel takes to reach where the stream lands (1 = it
#                reaches it). They never fly on past a surface the stream hits,
#                except for `cling`.
#   cling        seconds a stream puff drawn with a `particle` lives on past the
#                wall or floor the stream hits, sliding along it (its definition's
#                `collide = plane`); 0, the default, ends it there
#   tube         segments (0-8), thick, soft, stream share: a drawn-line core from the
#                nozzle to where it lands (the menu's Flame core). While it draws, the
#                stream bursts keep that share of their particles
#   tubelook     intensity, swell (the far end's halo over the nozzle's), halo
#   tubecolors   r, g, b stops, 2 to 8, the nozzle's first, spread evenly along it;
#                put the fade in the colours (a line's intensity is not blended)
#   tubelicks    strength (0-2), scale (noise cells per map unit), speed (rising)
#   heat         radius at the nozzle, radius at the far end, strength, noise scale,
#                rise: heat shimmer along the stream, riding the owner's hand
#   heatland     radius, strength: a ball of heat where it lands
#   landing      bursts where it lands (ordinary bursts), every landingtics
#   scorch       shape, radius, life (tics)   scorchcolor r, g, b   scorchtics
#   light        radius, intensity, flicker 0..1 (at the nozzle)   lightcolor
#   landlight    radius, intensity (where it lands, same colour)
#   sounds       loop, start, stop
#   pilot        bursts for an idle pilot light
#   jets         count, spacing (map units), splay (degrees): side-by-side jets
#   sputter      fuel share, sound: below that share of fuel (Stream's fuelShare)
#                the jet coughs, and the sound plays as it catches again
#   flameout     bursts when the trigger lets go (not from an empty canister)
# GPU particles are drawn at min(the definition's maxsize, r_gpuparticles_maxsize).
# That cvar is 8 until it is raised in Developer options (GPU particle size cap), so big
# puffs show only then.
